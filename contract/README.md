## この回答で取っているポジション

### 著作権（5番）

法律上、プログラムの著作権は制作した者に発生し、契約に定めがなければ受託者に留まります
（著作権法第17条・第61条）。したがって藤原の認識は正しいが、**契約書に書かなければ
「聖建様が何の権利で使えるのか」が曖昧**になるため、次の切り分けを明記する。

| 区分 | 対象 | 扱い |
|---|---|---|
| 譲渡 | 教材、画面デザイン、聖建様固有の業務処理、DB設計、蓄積データ | 検収完了かつ代金完済時に移転（27条・28条を含む） |
| 留保 | 本人確認・顔照合・在席確認・視聴整合性の共通モジュール、開発基盤、共通ライブラリ | スペリオルに留保。無償・永続・再許諾不可の利用許諾を付与 |

**27条（翻案権）・28条（二次的著作物の利用権）は、譲渡契約に特掲しないと移転しません**
（著作権法第61条第2項）。譲渡すると決めた以上、書き漏らすと後で揉めます。

### ソースコード（6番）

先方の要求は「進捗確認のため」と明記されている。目的を2つに分解して別々に応じる。

- 進捗の可視化 → 週次報告書＋隔週デモ＋GitHub の Issue/Projects のみ閲覧権限
- 継続性の担保 → **ソースコードエスクロー**（第三者預託）＋設計書一式の納品

それでも納品を求められた場合は、検収完了かつ代金完済後に、用途限定・転用禁止の条件付きで応じる余地を残してある。

## 最大のリスク — 10番と6番の組み合わせ

**「全額前払い」＋「返金特約」＋「毎週ソースコード共有」が同時に成立すると、
入金後に返金請求を受けつつコードだけ残る形が作れてしまいます。**

全額前払いを受け入れたのは、資金リスクと与信リスクが下がることの対価として
350,000円を値引きしたためです。返金条件が広いとその前提が崩れます。
**契約書案を見る前に署名しないこと。**
